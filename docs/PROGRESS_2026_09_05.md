## Outstanding issues, in order

1. **Complete G3 capture.** The last inspected attempt stopped before model
   loading because its bridge SHA-256 argument was not 64 lowercase hex digits.
   Use a digest computed from the exact bridge library bytes. Preparation,
   source revision, library identity and session commands must agree; capture
   all three processes without competing builds/tests. Keep every raw sample
   and audit any rejection under the frozen protocol.
2. **Verify and retain the result.** Reconstruct correctness, coverage and
   timings, verify the closed ten-file bundle, and add it through the normal
   review workflow. Only then promote G3 to complete.
3. **Keep timing claims tied to the measured boundary.** The same-Q8 fallback
   clones and hashes FP32 weights before computing. Projection hooks clone
   inputs/outputs, and isolated native-work timing is unavailable. Report these
   costs, startup and peak memory explicitly when interpreting generation data.
4. **Consolidate reviewed work.** The ordinary local main checkout is stale and
   dirty. Current integration/review commits are ahead of main, and existing
   hosted CI does not certify these latest improvements. Preserve the old
   checkout while reviewing and integrating the current branch.
5. **Select a license before publication.** The repository still has no
   maintainer-selected license. No license choice is inferred here.

Schedule tuning, AVX2, broader linear coverage, general `torch.compile`, fusion
and multicore are optional G4 work after the model evidence, not missing G3
requirements.
